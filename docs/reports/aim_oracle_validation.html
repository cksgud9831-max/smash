Solver Validation — 솔버가 자기 방정식을 안정적으로 푸는가

Ground Truth → Oracle Solver → Residual. 물리 모델이 "실제 세계에서" 정확한지가 아니라, 솔버 수치해석 자체의 건전성을 확인하는 단계입니다.

오라클의 정확한 역할 (지난 리뷰에서 지적된 부분)

오라클은 진짜 궤적을 HitEquation + NewtonSolver + ProjectileModel에 직접 묶어서 푼 결과입니다. 그런데 이 솔빙 스택은 실제 알고리즘 경로와 동일한 코드입니다 — 즉 오라클과 실제 해의 차이는 "노이즈 있는 관측이 완벽한 지식 대비 얼마나 비용을 치르는가"는 보여주지만, 솔빙 수식 자체에 계통적 오류가 있어도(예: 부호 실수) 양쪽이 똑같이 틀려서 차이는 0으로 나올 수 있습니다.

독립적으로 검증되는 부분과 아닌 부분을 나누면:

독립 검증됨 — CoordinateTransform.image_to_world(픽셀+레이저거리+플랫폼자세 → 월드좌표 복원). 오라클은 이 경로를 아예 안 거치고 진짜 좌표를 직접 받으므로, 노이즈 없는 조건에서 오차가 0에 가깝다는 건 이 복원 체인에 계통적 버그가 없다는 실질적 증거입니다.
독립 검증 안 됨 — HitEquation/NewtonSolver/ProjectileModel 자체의 물리적 타당성. 여기서 확인되는 건 "수렴성"(근을 안정적으로 찾는가)이지 "그 근이 실제 물리를 올바르게 반영하는가"가 아닙니다. 물리식 자체(중력 낙하 닫힌해)는 별도로 tests/test_projectile_model.py에서 손으로 유도한 공식과 대조해 독립적으로 검증돼 있습니다.

Robustness — 노이즈·기동·손떨림에 대한 강건성

Ground Truth → 합성 센서 관측(노이즈 주입) → aiming_engine → Ground Truth와 비교. 관측이 불완전할 때 실제로 얼마나 벗어나는지 측정합니다.
